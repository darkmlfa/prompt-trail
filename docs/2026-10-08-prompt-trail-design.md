# prompt-trail 설계

- 날짜: 2026-10-08
- 상태: 대화로 설계 승인됨, 스펙 검토 대기
- 위치: `~/.claude/plugin-sources/prompt-trail/` (git 저장소, GitHub `darkmlfa/prompt-trail`)
- 개발 중 로드: 이번 세션의 mods 폴더에 있는 `~/.claude/dev-mods/46ccabd9-f29b-4be9-9bf2-3af640d5ea47/prompt-trail`은
  위 폴더로 가는 링크라서, 파일을 고치면 핫 리로드된다.
- 대상: Claude Code 2.1.294, 터미널 fullscreen(`tui: fullscreen`), 어두운 테마

## 1. 목적

이번 세션에서 직접 입력한 프롬프트를 한눈에 되짚어 보게 한다. 입력창 바로 위 band에서
token-weather 줄 위에 테두리 박스를 두고, 프롬프트마다 원문 첫 줄과 짧은 요약을 보여준다.

## 2. 요구사항

| # | 요구 | 출처 |
|---|---|---|
| R1 | token-weather 바로 위에 구분선(테두리) 박스 | 첫 요청 |
| R2 | 이 세션에서 입력한 프롬프트 목록 | 첫 요청 |
| R3 | 프롬프트마다 대략적인 묘사 최대 2줄 | 첫 요청 |
| R4 | 박스 안 텍스트 최대 10줄, 넘치면 스크롤 | 추가 요청 |
| R5 | 항목 = 원문 첫 줄 + Haiku 요약(최대 2줄) | 선택지에서 고름 |
| R6 | 프롬프트마다 텍스트 색 전체를 다르게 | 추가 요청(정정) |
| R7 | 항목 앞에 내용에 어울리는 이모지 | 추가 요청 |

## 3. 화면

```
╭─ 이번 세션 프롬프트 (12) ───────────────── ↑4 ─╮   ← 테두리: 흐린 회색
│ 📏  9  높이도 제한을 둬서 텍스트 10줄이 최대…  │   ← 9번 색, 굵게
│        → 박스 최대 10줄, 넘치면 스크롤         │   ← 9번 색, 보통 굵기
│ 🎨 10  프롬프트마다 색상 다르게 하고 앞에 이…  │   ← 10번 색, 굵게
│        → 항목별 색상과 내용에 맞는 이모지 추가 │   ← 10번 색, 보통 굵기
╰────────────────────────────────────────────────╯
 ☂  Showers  67% of context  134.4k / 200k            ← token-weather (손대지 않음)
```

### 3.1 박스

- band 폭(`e.props.bodyColumns`)을 전부 쓴다.
- 테두리는 둥근 모서리(`╭╮╰╯`)이고, 색은 흐린 회색이다.
- 위 테두리 왼쪽에 제목 `이번 세션 프롬프트 (N)`을 넣는다. N은 항목 수다.
- 위로 가려진 행이 있으면 위 테두리 오른쪽에 `↑k`, 아래로 가려진 행이 있으면 아래 테두리 오른쪽에 `↓k`를 넣는다.
- 항목이 하나도 없으면 박스를 그리지 않는다.
- 테두리는 직접 그린다. 제목과 스크롤 표시를 테두리 안에 넣기 위해서다. 내용 행은 레이아웃 엔진이
  잘라내게 해서(`wrap="truncate-end"`), 글자 폭 계산이 조금 틀려도 오른쪽 테두리가 어긋나지 않게 한다.

### 3.2 항목

```
{이모지} {번호}  {원문 첫 행}       ← 1행, 넘치면 …
        → {요약 1행}                ← 요약은 최대 2행
          {요약 2행}
```

- 원문은 줄바꿈을 포함한 연속 공백을 한 칸으로 합친 뒤, 첫 행에 들어가는 만큼만 보여준다.
- 요약은 단어 단위로 최대 2행에 나누고, 넘치면 끝을 …로 자른다.
- 번호는 세션 안에서 입력한 순서다(1부터). 자릿수가 늘면 번호 칸 폭도 함께 늘린다.
- 글자 폭: 한글·한자·전각 문자와 이모지는 2칸, 나머지는 1칸으로 센다.

### 3.3 색 (R6)

- 항목의 모든 텍스트(번호, 원문 행, 화살표, 요약)를 그 항목의 색으로 칠한다. 흐리게(dim) 하지 않는다.
- 원문 행은 굵게, 요약은 보통 굵기로 쓴다.
- 6가지 색을 번호 기준 `(n - 1) % 6`으로 돌려 쓰므로, 붙어 있는 항목끼리는 항상 색이 다르다.

  | 순서 | 색 | 값 |
  |---|---|---|
  | 1 | 하늘 | `#5fd7ff` |
  | 2 | 분홍 | `#ff87d7` |
  | 3 | 노랑 | `#ffd75f` |
  | 4 | 초록 | `#87d787` |
  | 5 | 보라 | `#af87ff` |
  | 6 | 주황 | `#ffaf5f` |

  모두 256색 팔레트에 정확히 있는 값이라, truecolor가 아닌 터미널에서도 같은 색으로 나온다.

### 3.4 이모지 (R7)

- Haiku가 허용 목록에서 하나를 고른다.
- 허용 목록의 조건: 코드 포인트 하나, 터미널 폭 2칸(East Asian Width `W`), 변형 선택자(VS16)·ZWJ 없음.
  폭이 일정하지 않은 이모지를 쓰면 오른쪽 테두리가 어긋나기 때문이다.
- 30개 안팎으로 둔다. 후보: 🔧 🐛 ✨ 📝 🎨 🚀 🔍 ❓ 📦 🧪 📏 💡 ✅ ❌ 🧹 📋 🎯 🧩 🔑 🌐 📊 🔀 ⏪ 🤔 💬.
  구현할 때 위 조건을 스크립트로 확인해 확정한다.
- 목록에 없는 이모지가 오거나 요약에 실패하면 💬, 요약을 기다리는 동안은 ⏳를 쓴다.

### 3.5 높이와 스크롤 (R4)

- 박스 안 행 수는 `min(10, 전체 행 수)`이다. 위아래 테두리 2행은 따로 센다.
- band 공간(`e.props.maxRows`)이 모자라면 박스 안 행 수를 `maxRows - 2 - (박스 아래 행 수)`로 줄여서
  token-weather 줄이 밀려나지 않게 한다. 박스 아래 행 수는 아래쪽 plugin이 트리를 그렸으면 1(token-weather는
  한 줄), 엔진 기본 그림이면 0으로 본다. 2행보다 적어지면 박스를 그리지 않는다.
- (2026-10-08 실제 세션 확인 후 변경) 엔진은 band 안에 다 들어가는 트리에는 휠을 보내지 않고 대화창을 스크롤한다.
  그래서 박스는 두 상태를 둔다.
  - 접힌 상태(기본): 박스 안 최대 10행, 박스 자체 창. 이 상태에서 휠은 대화창을 스크롤한다(실측: 휠 이벤트가
    band에 한 번도 오지 않음, band 높이 35행). 숨은 행이 있으면 아래 테두리에 `[▲] [▼]`를 두어 클릭마다 3행씩
    움직인다. band에 포커스가 있을 때(클릭, ctrl+x tab) PageUp/PageDown은 박스 한 화면씩, Home/End는 끝까지 움직인다.
    폭이 모자라면 ▲▼를 먼저 뺀다.
  - 펼친 상태: 아래 테두리 오른쪽의 `[펼치기 ▾]`를 누르면 목록 전체를 그린다. band보다 높으면 엔진이 band 창을
    맡는다(키로 스크롤; 문서상 휠도 이 경우에만 band로 간다). 목록이 band 안에 들어가면 전체가 그대로 보인다.
    펼칠 때 맨 아래(최신)로 이동한다(`$.ui.scroll`).
    `[접기 ▴]`를 누르면 접힌 상태로 돌아가 맨 아래를 따라간다.
  - band가 좁아 버튼이 들어가지 않으면 아래 테두리만 그린다. `/clear`를 하면 접힌 상태로 돌아간다.
- 새 프롬프트가 들어오면 맨 아래로 이동한다. 요약이 도착해 행 수가 바뀔 때, 맨 아래에 있었다면
  맨 아래를 유지하고 위로 올려 둔 상태였다면 그 위치를 유지한다.

## 4. 동작

### 4.1 프롬프트 수집

- `prompt.submit`에서 `e.origin.kind`가 `composer`(터미널에서 직접 입력, 작업 중 보낸 메시지 포함) 또는
  `bridge`(Remote Control)인 것만 담는다. 알림, 예약 작업, 다른 세션, plugin이 보낸 프롬프트는 뺀다.
- `/`로 시작하는 텍스트(슬래시 명령)는 담지 않는다.
- 훅은 상태에 항목을 하나 추가한 뒤 바로 `next(e)`를 부른다. 프롬프트 전송을 늦추지 않으며,
  예외가 나도 프롬프트는 그대로 진행된다.

### 4.2 요약 (R3, R5, R7)

- `session.start`에서 시작한 타이머(`$.clock.every`, 1초 간격)가 대기 중인 항목을 한 번에 하나씩 처리한다.
  최신 항목부터 처리한다.
- 문맥: 세션 기록(`$.session.messages()`)에서 그 프롬프트 바로 앞 Claude 답변의 끝 1,500자.
  짧은 답("진행해", "1번으로")이 무슨 뜻이었는지 요약하기 위해서다.
- 호출: `$.model.complete({ model: 'haiku', system, prompt, maxTokens: 300, timeoutMs: 20000 })`.
- 응답 형식: JSON `{"emoji": "…", "summary": "…"}`. 요약은 한국어 한 문장으로, 사용자가 무엇을
  요청하거나 결정했는지를 70자 이내로 쓴다.
- 검증: JSON으로 읽히지 않거나 요약이 비어 있으면 실패로 본다. 코드 펜스로 감싼 JSON은 벗겨서 읽는다.
  이모지가 목록 밖이면 💬로 바꾼다.
- 실패하면 최대 2번까지 시도한다. 그래도 실패하면 실패로 표시하고, 원문에서 첫 행에 다 들어가지 못한
  나머지를 요약 자리에 최대 2행으로 보여준다. 나머지가 없으면 요약 행을 그리지 않는다.
- 비용: 프롬프트마다 Haiku 호출 1번, 1~2천 토큰 정도.

### 4.3 이전 프롬프트 채우기 (가능한 범위에서)

- `session.start`에서 목록이 비어 있으면 세션 기록을 읽어 최근 사용자 메시지 50개까지 채운다.
  각 항목의 문맥은 기록에서 바로 앞 Claude 답변으로 정한다.
- 거르는 것: 도구 결과가 든 메시지, `<`로 시작하는 태그 행(명령 기록, 시스템 알림),
  스킬 본문(`Base directory for this skill:`로 시작), 중단 표시(`[Request interrupted`로 시작),
  압축 요약(`This session is being continued from a previous conversation`으로 시작).
- 한계: 작업 중에 보낸 메시지는 세션 기록에 일반 메시지가 아니라 따로 저장되므로 빠질 수 있다.
  실제 세션에서 결과를 보고 필터를 맞춘다.

### 4.4 상태 수명

- 목록, 스크롤 위치, 맨 아래 따라가기 여부는 `$.state`(세션 범위)에 둔다. mod를 고쳐 다시 로드해도 남는다.
- `session.end`의 `reason`이 `clear` 또는 `resume`이면 목록과 스크롤 상태를 비운다.
- 세션이 끝난 뒤까지 보관하지는 않는다.

## 5. token-weather와 같이 쓰기

- 방식 A(채택): `ui.render`의 `AbovePrompt` 훅에서 `await next(e)`로 아래쪽 plugin(token-weather)이
  그린 트리를 받고, 박스 아래에 붙여 하나의 트리로 돌려준다.
- 설문(`e.props.hasSurvey`)이 band를 쓰는 동안이나 표면이 터미널이 아니면 손대지 않고 `next(e)`를 돌려준다.
- 위험: 두 plugin은 같은 user 계층에 있고, 계층 안 순서는 문서에 없다. token-weather 훅이 더 바깥이면
  그 훅이 `next`를 부르지 않으므로 이 mod의 훅이 실행되지 않는다. 로드한 뒤 화면으로 확인한다.
- 대안 B: 순서가 반대이면 token-weather 한 줄(아이콘, 퍼센트, 토큰 수, 추세 차트)을 이 mod 안에서 그리고,
  설치된 token-weather는 끈다. B로 바꾸기 전에 사용자에게 알린다.

## 6. 구성

| 파일 | 역할 |
|---|---|
| `.claude-plugin/plugin.json` | 이름 `prompt-trail`, 버전, 설명, `types` 경로 |
| `.claude-plugin/marketplace.json` | 저장소를 marketplace로 만든다: `plugins: [{ "name": "prompt-trail", "source": "./" }]` |
| `README.md` | 화면 설명, 설치 명령 `/plugin install prompt-trail --marketplace darkmlfa/prompt-trail` |
| `.gitignore` | `.claude-plugin/types/`(엔진이 로드할 때마다 쓰는 타입 파일) |
| `hooks/hooks.json` | `{ "modules": ["./register.tsx"] }` |
| `hooks/register.tsx` | 이벤트 연결(`prompt.submit`, `session.start`, `session.end`, `ui.render`, `ui.scroll`), 그리기, 요약 타이머 |
| `hooks/layout.ts` | 순수 함수: 글자 폭, 한 행 자르기, 단어 단위 2행 나누기, 항목을 행 목록으로, 10행 창 계산, 테두리 문자열 |
| `hooks/summarize.ts` | 순수 함수: Haiku 프롬프트 만들기, 응답 파싱과 검증, 이모지 허용 목록 |
| `hooks/capture.ts` | 순수 함수: 수집 규칙(origin, `/`), 세션 기록 필터, 문맥 찾기 |
| `types/index.d.ts` | `PluginState['prompt-trail']` 계약 |
| `hooks/*.test.ts` | 테스트 |

순수 함수 모듈은 `$`를 모른다. 그래서 단위 테스트를 엔진 없이 짤 수 있다.

상태 계약:

```ts
type Entry = {
  id: string
  n: number                    // 세션 안 순서, 1부터
  text: string                 // 원문
  context?: string             // 바로 앞 Claude 답변의 끝 1,500자
  status: 'pending' | 'done' | 'failed'
  attempts: number
  emoji?: string
  summary?: string
}

interface PluginState {
  'prompt-trail': {
    entries: Entry[]
    offset: number             // 박스 안 창의 첫 행
    follow: boolean            // 맨 아래를 따라가는지
    expanded: boolean          // 펼친 상태인지
  }
}
```

## 7. 오류 처리

- 모든 훅은 예외를 잡고 엔진 기본 동작(`next(e)`)으로 돌아간다. `prompt.submit` 훅은 어떤 경우에도
  프롬프트를 막지 않는다.
- 요약 실패는 그 항목의 표시에만 영향을 준다(4.2).
- 그린 트리가 검증에 실패하면 엔진이 자기 것을 그린다(박스 없음). 원인은 transcript의 흐린 줄과
  디버그 로그로 확인한다.

## 8. 검증

### 8.1 자동

- `claude plugin validate`, `tsc -p`, `claude plugin test`
- layout: 한글·이모지 2칸 폭, 한 행 자르기와 …, 2행 나누기, 10행 창의 offset 범위, `↑k`/`↓k` 계산
- summarize: 정상 JSON, 코드 펜스로 감싼 JSON, 깨진 JSON, 목록 밖 이모지가 💬로 바뀌는지
- capture: origin 필터, `/` 명령 제외, 메타 행 필터, 문맥 찾기
- 훅(터미널 표면에 `AbovePrompt` mount):
  - 항목이 0개면 박스 없음
  - 항목이 12개면 박스 안 10행과 `↑` 표시
  - `ui.scroll`로 창이 움직임
  - 아래쪽 훅이 그린 한 줄이 박스 아래에 붙음

### 8.2 실제 세션

- 박스와 token-weather가 위아래로 같이 보이는지(실행 순서 확인)
- 휠 스크롤, 새 프롬프트가 들어올 때 맨 아래로 이동하는지
- 요약과 이모지가 몇 초 안에 도착하는지
